# CLAUDE.md

Neuro-Fit — browser squat coach. Camera → MediaPipe pose → local metrics/triggers → Gemini coaching. No backend, no accounts, no persistence beyond localStorage settings. Squat is the only exercise.

## Commands
- `npm run dev` — Vite dev server (5173) · `npm run build` — `tsc -b && vite build` · `npm run typecheck` — types only
- `npm run check:squat` — pure-module unit asserts on synthetic data (Node/esbuild, no browser). **Run after touching `squat/`, `session/`, or `debug/evalLog.ts`.**
- `npm run test:midset` — ⚠️ **stale**: exercises the mid-set request shape, which no longer exists in the app. Passing here says nothing about `callPostSet`/`callPostWorkout`.

## Stack & layout
- React 18 + TS + Vite. Tracker code under `src/neurofit/` (entry `App.tsx`, repointed in `src/main.tsx`); the marketing site is a second app under `site/`.
- **Monorepo, one push deploys both.** Repo root IS `NEUROFIT/` (github.com/LLAMAlucas/Neurofit-Website). Two Vercel projects split by root directory: `neurofit-website` → `site/` → **neurofit-training.com**; `neurofit-tracker` → `.` → **try.neurofit-training.com**. The live `.env.local` now sits inside the working tree — `.gitignore` covers it with unanchored `.env*` and `*.local`; do not narrow those.
- MediaPipe Tasks (`@mediapipe/tasks-vision`) with **vendored** WASM + lite model in `public/mediapipe/wasm/` + `public/models/` (runs offline).
- Gemini is browser-direct with the **user's own key**, typed into Settings and kept in localStorage (`neurofit.apiKey`, `getApiKey`/`setApiKey` in `ai/gemini.ts`). App runs fully without a key (AI shows disabled).
- **Never read the key from `import.meta.env` outside a `import.meta.env.DEV` fence.** Vite resolves env at BUILD time and inlines it verbatim, so a key read unfenced is readable by anyone who loads the bundle — and the tracker is now served publicly at `try.neurofit-training.com`. The `.env.local` + `envPrefix` path survives for `npm run dev` ONLY, behind that fence; production builds drop the branch. Verify after touching this: build, then grep `dist/` for the key.
- The key goes in the `x-goog-api-key` **header**, never the query string (a URL-borne key lands in proxy logs, Referer headers and history).
- **Module boundary — convention, not tooling-enforced:** `squat/`, `vision/`, `session/`, `ai/` (except `gemini.ts`), `pose/` (except `poseLandmarker.ts`) are PURE (no React/DOM). Only `components/`, `hooks/`, `poseLandmarker.ts`, `gemini.ts` touch the browser. The pure modules are what `check:squat` can test in Node — keep it that way.

## Philosophy ("neurofit-trigger-logic-v2")
- **MediaPipe triggers + narrates; Gemini judges.** No local metric self-diagnoses a fault — local code only decides "a movement is worth examining" (a trigger); Gemini decides if it's real and what to cue. Don't add fault verdicts to the local layer.
- **Every threshold in `config.ts` is UNVALIDATED** (n=1: the developer, a long-femur outlier; a few n=2). Treat no number as correct — multi-body calibration is the blocking dependency. When you change one, comment WHY (observed behavior).
- All timing/persistence is in **milliseconds**, never frame counts (frame rate is adaptive).

## Rep counting & depth (non-obvious rationale)
- Reps key off **vertical hip displacement** `depthRatio=(hUp−h)/hUp`, NOT 2D knee angle: knee angle barely moves head-on (sagittal flex projects onto the camera's depth axis), so it only works side-on; hip-Y drops in both views.
- Attempt detection (`repDownRatio`) is orientation-agnostic. Whether it **counts** (`repCounts()`): **side** needs bottom hip-vs-knee gap ≥ preset `targetGap`; **front** needs `bottomDepthRatio` ≥ per-preset `frontRatioTarget` (`above 0.40`, `parallel 0.60`; `full`→parallel target). Front is **count-only, no depth GRADE**; deeper always counts; a null ratio never counts.
- Depth uses hip-Y vs knee-Y, never joint angles, vs the Settings preset (`DEPTH_PRESETS` full/parallel/above, `useDepthPreset`, default parallel).
- **Depth is NEVER a realtime cue** (product rule — the rep counter IS the realtime depth feedback): counting never calls `requestTrigger`. Depth stays valid post-set/post-workout + as context. Uncounted reps are recorded (`RepRecord.counted=false`, plus `depthGap`) and sent to Gemini as `uncounted_reps` so cut-short reps aren't invisible.
- **Send the number that DECIDED the rep.** `depthRatio` is agnostic and can read *higher* on a side rep that failed the gate than on one that passed (measured: 0.688 uncounted vs 0.658 counted) — because side counting is decided by the hip-vs-knee **gap**. So `uncounted_reps` carries `{measured, target, band}` and the basis is sent once as `depth_context.depth_basis` (`"hip_knee_gap"` side / `"depth_ratio"` front), governing both it and `achieved_depth`. Adding a new depth-ish field → say which basis it is in.

## Orientation & metrics
- Sets alternate side/front; each plane's faults are only checked from the view that can see them. Orientation locks while **STANDING** — facing score (`shoulderXSep/torsoLen`) is posture-coupled (squatting inflates it), so `ORIENTATION.SCORE` is tuned for standing.
- Per-check angle tolerance (`checkToleranceDeg`) gates each metric; outside tolerance → `"unknown"`, never `"warn"`. Occlusion is never a fault.
- SAGITTAL (side-only): depth, forwardLean, buttWink, trunk/shin angle. FRONTAL (front-only): kneeValgus, levelness, kneeSymmetry, hipShift, stance width. AGNOSTIC: repCount, velocity, eccentricControl, depthRatio, hip-Y timing.

## Triggers (`TRIGGERS` in `config.ts`, all UNVALIDATED)
- **Baselines come from the WARM-UP REPS ONLY.** `BaselineTracker` enforces a sample *cap*, not a rep window — it has no rep index — so every `record()` call site is gated on `rep.index <= TRIGGERS.baselineReps` in addition to the `repFeedsBaseline` depth-hygiene gate. Without the window gate a late rep silently completes the baseline: 2026-08-02 set 3 had rep 1 fail hygiene and **rep 6** become sample #2, resolving the baseline on the last rep of the set, after every trigger had run against `null`. The trigger layer reported no baseline while the payload reported 26.9°. Trigger eligibility is `rep.index > baselineReps`, so the recording window must stay its exact complement. Consequence, deliberate: a failed warm-up rep disarms the dependent checks for the WHOLE set — which is why the payload must say so (below).
- **T1** forward-lean (side, baseline-relative), **T2** eccentric (agnostic, descent-spike/bounce), **T7** valgus (front). Fire behind 150 ms `PersistenceGate`s, once/rep, after warm-up (reps 1–2 = per-set baseline via `BaselineTracker`). Requested via `CoachingCoordinator.requestTrigger`; same-rep triggers within 500 ms merge. **Mid-set cues were removed** (12–34 s latency on ~40 s sets) — firing a trigger now only archives a peak-severity frame for the post-set debrief; no text is produced mid-set.
- **Faults are judged THROUGHOUT the rep, not at the bottom** (2026-07-31 eval run). The per-frame machinery already spans descent→bottom→ascent (`observeDescentFrame` runs whenever the tracker `isDown`); only the **depth gates** and `AGGREGATED_METRICS` membership were narrowing it. T7's worst cave was measured during the ASCENT, below the old 0.30 gate — it missed the persistence window by ~73 ms and fired zero times in 30 reps. Gates now: lean **0.3**, valgus **0.15**, hipShift **0.3**. Depth stays bottom-only by definition. If you narrow a gate, you are deciding a fault can only exist in part of the rep — say why.
- `AGGREGATED_METRICS` (in `checks.ts`) = the metrics read worst-of-frames rather than from the bottom snapshot: `kneeValgus`, `shoulderHipLevelness`, `forwardLean`, `hipShift`. Aggregating a metric whose shallow-depth readings are non-physical needs a depth gate in the same change (hipShift peaks at 1.44 hip-widths near lockout vs a 1.5 "falling over" bound).
- **Trigger layer ≠ metric layer.** A metric `warn` is worst-of-frames, ungated. A trigger is gated + persistence-held. `RepRecord.triggeredMetrics` (snapshotted from `firedThisRepRef` at rep-complete) is the trigger truth; `metrics[id].status` is not. `triggers_fired` in the payload MUST read the layer that actually decided each fault, or the eval log and the AI payload tell different stories and neither can audit the other.
- **T6** velocity-collapse is CONTEXT ONLY, never a cue (deliberate silent-fatigue exception).
- **T10 knee-symmetry is structurally broken** — n=2 showed it anti-correlated with knee cave (reads LOWER on real caves). DEMOTED to context-only; **T7 valgus is the real cave detector.** Don't re-enable it. `shoulderHipLevelness` likewise demoted (aspect-distorted jitter). Both still computed + sent as raw context but assert no fault anywhere.
- **T11** hipShift fires baseline-relative + scored (`RepRecord.shiftTriggered`); its absolute warn is kept only for the panel/context. Still the least trustworthy trigger — one correct fire in four on n=1; needs a dedicated calibration session.
- **T2 bounce has never fired.** `bounceMaxMs` was 150 ms against a measured reversal range of **268.7–1301.5 ms** across 30 reps — provably unreachable. Raised to **300 ms** and gated on `reachedDepth`, because the only sub-300 ms rep in the dataset was a deliberate quarter squat (raising it ungated just converts a dead signal into a shallow-rep false positive). ⚠️ Still zero true positives behind the number.
- **T2 descent is baseline-relative, so a slow warm-up poisons it.** `descentSpikeMult` 1.5 → **2.0**: when reps 1–2 are slower than the working reps the baseline is depressed and normal reps trip the gate (2 false positives in one set at 1.5×). Real users warm up slowly, so this generalises — don't lower it back without checking the warm-up tempo spread.
- Severity zones (`severityFor`/`SEVERITY`) are display/report ONLY — they no longer fire the coach.

## Gemini layer (`ai/gemini.ts`)
- Two live tiers: `callPostSet` (images) and `callPostWorkout` (text-only). Shared `geminiGenerate` = system prompt + JSON payload + inline JPEGs. The mid-set tier is GONE — `requestCoaching()` survives in `gemini.ts` as dead code with zero callers, and `scripts/test_midset.ts` (`npm run test:midset`) still exercises that removed path, so a green run there proves nothing about the live shape.
- Model **`gemini-3.6-flash`** (env `GEMINI_MODEL`; migrated from `3.5-flash` 2026-07-25 — drop-in, request shape unchanged, A/B-verified 200/STOP on a replayed real post-set + post-workout payload). Thinking IS sent (`thinkingConfig.thinkingLevel`: post-set `medium`, post-workout `low`). **Omit temperature** on 3.x (1.0 default; lowering risks thinking loops). `maxOutputTokens`: post-set **8192**, post-workout **4096** — thinking draws from the output budget, so a tight cap truncates mid-thought. Measured headroom on 3.6: post-set 1859 thought + 246 output of 8192; post-workout 489 + 343 of 4096.
- No rate limiter (it gated mid-set only, and went with it). Spend is bounded by the **usage ledger** instead: `usage/ledger.ts` (PURE — all arithmetic, `nowMs` injected) + `usage/usageStore.ts` (localStorage). Rolling-window quota, not calendar-month (no reset job, no timezone call, can't be gamed by waiting for the 1st). The quota gate **fails open** — a bookkeeping error must never block a paying user's coaching. Workouts are **upsert-by-`sessionId`**, which is what makes `completionRate` meaningful (recording only on finish reads a permanent 100%). ⚠️ Client-side = a spend guard for honest users, NOT a security control; the API key is inlined into the bundle. Real enforcement needs the key behind a proxy.
- **Analysis fires ONLY on explicit user click** (product decision): post-set on "Next set" (`requestPostSet`), post-workout on "End workout"/Finish. The last set (ended via End Workout) never generates a post-set — nothing fires automatically.
- `extractText` returns `{text, finishReason, usage}`. **finishReason ≠ STOP (e.g. MAX_TOKENS) = truncation** → surfaced as an error, NOT shown as a normal result, and logged (with per-call token usage).
- **View-awareness ↔ payload honesty (keep in sync):** the system prompts forbid the model asserting a plane the camera can't see. The PAYLOAD must match — `firePostSet` nulls SAGITTAL fields on front and FRONTAL fields on side, using **null (not 0/false — false reads as "checked, absent")**. New payload field → classify its plane and null it off-view. `landmarkImplausible` is likewise front-only: it reads frontal-plane geometry, and edge-on the hip width collapses to ~0.007 as a denominator, which flagged **18/18 side reps unreliable** and silently deleted fatigue context from every side set. Those quantities are undefined edge-on, not merely extreme — widening bounds would not have fixed it.
- **Silence from a disarmed check is NOT a pass.** `baseline.valid` + `baseline.checks_disarmed` (names only the checks this view could have run) tell the model which triggers never armed; `POSTSET_SYSTEM` rule 1a forbids reading an empty `triggers_fired` as clean form, **and** forbids substituting an explanation for anything a disarmed check could have caused ("this was not X but rather Y" is the exact failure). Distinct from `baseline_frames_included`, which is only about photos — a set can have both photos and no usable baseline. Without this, set 3 of the 2026-08-02 run was told *"spinal alignment and balance remained solid, no movement faults triggered"* about a set containing a **59.3° lean**.
- **The user never sees a normalized number.** Gap / depth-ratio / velocity-ratio / shift / valgus values are image coordinates — `-0.0023` reads as a rounding error, not "a hair above parallel". The payload carries a precomputed band (`uncounted_reps[].band` via `depthShortfallBand`, `context.velocity_band` via `velocityBand`, both PURE in `checks.ts`; thresholds in `DEPTH_SHORTFALL_BANDS`, keyed by basis because gap and ratio units aren't comparable) and rules 6a/6b let the model speak ONLY the band. **Degrees and rep numbers stay quotable** — they're real units. Severity language scales via `triggers_fired[].severity` + `baseline_multiple` (peak ÷ this set's baseline): `severity` alone is flat, since a 0.32 and a 0.66 hip shift are both "critical" and the debrief called the 2.6× one *"slightly off-center"*. Keep the raw numbers IN the payload — rule 3a's fatigue gate is defined on `velocity_collapse_ratio` — just never spoken.
- **Debriefs render VERBATIM — no markdown parser.** `PostSetReview`/`SynthesisReport` put `review.text` straight into a `<p class="ai-msg">`, so `**bold**` reaches the user as literal asterisks. `.ai-msg` sets `white-space: pre-line` to keep the model's paragraph breaks (default `normal` collapsed a 5-line debrief to 2). Both system prompts' rule 8 forbids markdown for this reason — if you ever add a markdown renderer, relax rule 8 in the same change.
- **Causal claims are evidence-bound (prompt rules `3a`/`5`).** The model previously asserted "fatigue" in every set, including two where `context.velocity_collapse_ratio` was `null`, and contradicted `fault_trends[].worsened_with_fatigue: false` in the post-workout. Fatigue may now be claimed ONLY from `velocity_collapse_ratio < 1.0` (post-set) or `worsened_with_fatigue` (post-workout); later rep numbers are explicitly not evidence, and causation is banned in **both** prompts — fault→fault *and* context→fault (velocity may establish THAT a rep slowed, never that slowing caused a fault or a "drop in rep quality") (the ban lived only in `POSTSET_SYSTEM` until 2026-07-31 and leaked from the synthesis: *"which directly caused"*, about a trigger that hadn't fired). A session minimum can't localise fatigue either — the payload carries `velocity_ratios_by_rep`, and rule 3a permits attributing fatigue only to a rep whose OWN ratio is below 1.0 (both prior claims pinned it on reps measuring 1.18 and 0.95).
- **API kill-switch:** `geminiEnabled()` also honors a localStorage toggle (`neurofit.apiDisabled`, Settings/`useApiEnabled`) so you can exercise UI + tune raw numbers with zero API calls.

## Frame buffers & DON'T-FAKE gotchas
- `ai/frameBuffer.ts` (pure): `LandmarkBuffer` (full-rate, 3 s) + `ImageBuffer` (ring cap 30 ≈ **~7.5 s**, one 640×480 q0.75 JPEG/250 ms). CoachCamera captures/downscales; buffer stays DOM-free.
- **The ~7.5 s ring evicts baseline (reps 1–2) + early-set fault frames 5–12 s before the post-set call fires** (verified n=1, every set). FIXED via a per-set **frame archive** (`postSetFrameArchiveRef` in `useWorkout.ts`, no time limit): reps 1–2 bottom key frames archived at rep-complete (`archiveBaselineFrame`), one peak-severity frame per error TYPE archived at trigger time (`archiveFaultFrame`, direction-aware via `tagMoreSevere`). The ENTIRE archive is what post-set sends — the ring is NOT read by post-set. `PostSetData.baseline_frames_included` (0–2) tells the model how many baseline frames it got; `POSTSET_SYSTEM` rule 1 says 0 ⇒ "no baseline available", never fabricate. **Post-workout is TEXT-ONLY** (no frames — synthesizes over the per-set debrief texts). Archive is reset per set in `newSetTrackers`, AFTER the post-set send.
- Deferred — DO NOT FAKE: `presetIsMobilityBoundary` always `false` (no intent-capture signal — never tell Gemini a preset is a mobility boundary); `preset_reason` always `"preference"`; chest-cave has no landmarks (when T1 fires, the prompt asks Gemini to eyeball rounding from the image).

## State machine & dev tools
- `WorkoutPhase`: positioning → countdown → active → **set-review** → finished. Set-review is a two-stage overlay (`choice`→`post-set`) rendered as a **CoachCamera child so the MediaPipe model stays loaded between sets** — don't unmount CoachCamera.
- Training mode bodyweight|loaded (`useMode`, localStorage) flips valence (loaded: butt-wink a real trigger, excessive depth flagged) — framed in the prompt, not new geometry.
- **Dev-only eval logger** (`debug/evalLog.ts`, gated `import.meta.env.DEV`/`VITE_EVAL_LOG=1`): DESCRIPTIVE ONLY, never affects logic, inert in prod. Per-rep trigger table (every eligible trigger incl. did-NOT-fire + near-miss — false negatives only surface here) + per-Gemini-call observation (payload/frames/verbatim response/latency/finish_reason/tokens/skips). Exports JSON+MD; the `front_depth_gate` row validates the front depth targets. Pre-fill intended faults via `window.__neurofitEval.setScript({"1:3":"fast descent"})`.
- **`SCRIPT_PROTOCOL_V2`** (in `evalLog.ts`) is the ground truth labelling each rep of a calibration run; **`TEST_PROTOCOL.md`** is the human-readable version the lifter follows. **Change both together** — a drift between them silently mislabels the entire dataset.
