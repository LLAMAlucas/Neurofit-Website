# CLAUDE.md

Neuro-Fit — browser squat, push-up + pull-up coach. Camera → MediaPipe pose → local metrics/triggers → Gemini coaching. No backend, no accounts, no persistence beyond localStorage (settings, the usage ledger, Analyze notes). Three exercises, picked in the header (switching resets the workout); push-ups and pull-ups are documented in their own sections below and every push-up / pull-up threshold is n=0. A second product, **Analyze** (video form analysis of a clip the user already filmed), lives on its own page of the same app — see its section below.

## Commands
- `npm run dev` — Vite dev server (5173) · `npm run build` — `tsc -b && vite build` · `npm run typecheck` — types only
- `npm run check:squat` — pure-module unit asserts on synthetic data (Node/esbuild, no browser). **Run after touching `squat/`, `session/`, or `debug/evalLog.ts`.**
- `npm run check:pushup` — same style for `pushup/` (synthetic Winter-proportion body model → frames → session → payload → prompts). **Run after touching `pushup/`, `ai/prompts.ts`, `squat/dynamics.ts`, `squat/velocity.ts` or `debug/evalLog.ts`** — push-ups reuse those squat modules.
- `npm run check:pullup` — same style for `pullup/` (a hanging body under a bar, with chin, knuckles, kip swing and leg drive). **Run after touching `pullup/`, `ai/prompts.ts`, `squat/dynamics.ts`, `squat/velocity.ts`, `pushup/frame.ts`, `vision/orientation.ts` or `debug/evalLog.ts`** — pull-ups reuse those.
- `npm run check:analyze` — same style for `analyze/` (geometry, rep finder, key frames, payloads, prompt↔schema↔payload contract, answer parser, cost, saved notes, point tracker) **and** asserts the live coach's Gemini request bodies are byte-identical through `ai/requestBody.ts`. **Run after touching `analyze/`, `ai/prompts.ts`, `ai/requestBody.ts`, `ai/gemini.ts` or `pose/landmarks.ts`.**
- `npm run check:mirror` — the shared `chrome/` folders (tracker ⇄ site) are byte-identical, plus the `chrome/ascii.ts` asserts. **Run after touching either `chrome/`.**
- `npm run test:midset` — ⚠️ **stale**: exercises the mid-set request shape, which no longer exists in the app. Passing here says nothing about `callPostSet`/`callPostWorkout`.

## Philosophy ("neurofit-trigger-logic-v2")
- **MediaPipe triggers + narrates; Gemini judges.** No local metric self-diagnoses a fault — local code only decides "a movement is worth examining" (a trigger); Gemini decides if it's real and what to cue. Don't add fault verdicts to the local layer.
- **Every threshold in `config.ts` is UNVALIDATED** (n=1: the developer, a long-femur outlier; a few n=2). Treat no number as correct — multi-body calibration is the blocking dependency. When you change one, comment WHY (observed behavior).
- All timing/persistence is in **milliseconds**, never frame counts (frame rate is adaptive).

## Rep counting & depth (non-obvious rationale)
- Reps key off **vertical hip displacement** `depthRatio=(hUp−h)/hUp`, NOT 2D knee angle: knee angle barely moves head-on (sagittal flex projects onto the camera's depth axis), so it only works side-on; hip-Y drops in both views.
- Attempt detection (`repDownRatio`) is orientation-agnostic. Whether it **counts** (`repCounts()`): **side** needs bottom hip-vs-knee gap ≥ preset `targetGap`; **front** needs `bottomDepthRatio` ≥ per-preset `frontRatioTarget` (`above 0.40`, `parallel 0.60`; `full`→parallel target). Front is **count-only, no depth GRADE**; deeper always counts; a null ratio never counts.
- Depth uses hip-Y vs knee-Y, never joint angles, vs the Settings preset (`DEPTH_PRESETS` full/parallel/above, `useDepthPreset`, default parallel).
- **Depth is NEVER a realtime cue** (product rule — the rep counter IS the realtime depth feedback): counting never calls `requestTrigger`. Depth stays valid post-set/post-workout + as context. Uncounted reps are recorded (`RepRecord.counted=false`, plus `depthGap`) and sent to Gemini as `uncounted_reps` so cut-short reps aren't invisible.
- **Send the number that DECIDED the rep.** `depthRatio` is agnostic and can read *higher* on a side rep that failed the gate than on one that passed (measured: 0.688 uncounted vs 0.658 counted) — because side counting is decided by the hip-vs-knee **gap**. So `uncounted_reps` carries `{measured, target, band}` and the basis is sent once as `depth_context.depth_basis` (`"hip_knee_gap"` side / `"depth_ratio"` front), governing both it and `achieved_depth`. Adding a new depth-ish field → say which basis it is in.

## Orientation & metrics
- Sets alternate side/front; each plane's faults are only checked from the view that can see them. Orientation locks while **STANDING** — facing score (`shoulderXSep/torsoLen`) is posture-coupled (squatting inflates it), so `ORIENTATION.SCORE` is tuned for standing.
- **Every angle is in aspect space `[x·W/H, y]`** (since 2026-09-18) — trunk lean, knee/shin/foot angles, levelness, the facing score, camera roll (`squat/frame.ts`, `pose/facing.ts`, `vision/cameraAngle.ts`; `CoachCamera` passes the frame size). MediaPipe normalizes x by width and y by height, so a raw-coordinate angle is camera-dependent: one squat read ~19° of lean on the 16:9 laptop and ~48° on a portrait phone, and the facing score differed 3.2×. Points and spans stay normalized on purpose — y-only quantities (depth gap/ratio, travel, descent speed) and x/x ratios (valgus, stance, shift, symmetry) were aspect-invariant all along, so their thresholds did not move. **Every recorded session was 1280×720**: thresholds tuned on that footage were converted with `atan(tan θ · 16/9)` (lean warn 35→51, critical 50→65, facing anchors ×16/9) and T1's delta 10→12 was re-derived by replaying the recorded reps (`check:squat` "aspect replay"). Geometric-intent values (levelness 8/16, plausibility 60°, roll 8°) kept their numbers as real degrees. **Degrees quoted from runs before 2026-09-18 — including in this file — are normalized-space numbers**; convert before comparing.
- Per-check angle tolerance (`checkToleranceDeg`) gates each metric; outside tolerance → `"unknown"`, never `"warn"`. Occlusion is never a fault.
- SAGITTAL (side-only): depth, forwardLean, buttWink, trunk/shin angle. FRONTAL (front-only): kneeValgus, levelness, kneeSymmetry, hipShift, stance width. AGNOSTIC: repCount, velocity, eccentricControl, depthRatio, hip-Y timing.

## Triggers (`TRIGGERS` in `config.ts`, all UNVALIDATED)
- **Baselines come from the WARM-UP REPS ONLY.** `BaselineTracker` enforces a sample *cap*, not a rep window — it has no rep index — so every `record()` call site is gated on `rep.index <= TRIGGERS.baselineReps` in addition to the `repFeedsBaseline` depth-hygiene gate. Without the window gate a late rep silently completes the baseline: 2026-08-02 set 3 had rep 1 fail hygiene and **rep 6** become sample #2, resolving the baseline on the last rep of the set, after every trigger had run against `null`. The trigger layer reported no baseline while the payload reported 26.9°. Trigger eligibility is `rep.index > baselineReps`, so the recording window must stay its exact complement. Consequence, deliberate: a failed warm-up rep disarms the dependent checks for the WHOLE set — which is why the payload must say so (below).
- **T1** forward-lean (side, baseline-relative), **T2** eccentric (agnostic, descent-spike/bounce), **T7** valgus (front). Fire behind 150 ms `PersistenceGate`s, once/rep, after warm-up (reps 1–2 = per-set baseline via `BaselineTracker`). Requested via `CoachingCoordinator.requestTrigger`; same-rep triggers within 500 ms merge. **Mid-set cues were removed** (12–34 s latency on ~40 s sets) — firing a trigger now only archives a peak-severity frame for the post-set debrief; no text is produced mid-set.
- **Faults are judged THROUGHOUT the rep, not at the bottom** (2026-07-31 eval run). The per-frame machinery already spans descent→bottom→ascent (`observeDescentFrame` runs whenever the tracker `isDown`); only the **depth gates** and `AGGREGATED_METRICS` membership were narrowing it. T7's worst cave was measured during the ASCENT, below the old 0.30 gate — it missed the persistence window by ~73 ms and fired zero times in 30 reps. Gates now: lean **0.3**, valgus **0.15**, hipShift **0.3**. Depth stays bottom-only by definition. If you narrow a gate, you are deciding a fault can only exist in part of the rep — say why.
- `AGGREGATED_METRICS` (in `checks.ts`) = the metrics read worst-of-frames rather than from the bottom snapshot: `kneeValgus`, `shoulderHipLevelness`, `forwardLean`, `hipShift`. Aggregating a metric whose shallow-depth readings are non-physical needs a depth gate in the same change (hipShift peaks at 1.44 hip-widths near lockout vs a 1.5 "falling over" bound).
- **Trigger layer ≠ metric layer.** A metric `warn` is worst-of-frames, ungated. A trigger is gated + persistence-held. `RepRecord.triggeredMetrics` (snapshotted from `firedThisRepRef` at rep-complete) is the trigger truth; `metrics[id].status` is not. `triggers_fired` in the payload MUST read the layer that actually decided each fault, or the eval log and the AI payload tell different stories and neither can audit the other.
- **T6** velocity-collapse is CONTEXT ONLY, never a cue (deliberate silent-fatigue exception).
- **T10 knee-symmetry is structurally broken** — n=2 showed it anti-correlated with knee cave (reads LOWER on real caves). DEMOTED to context-only; **T7 valgus is the real cave detector.** Don't re-enable it. `shoulderHipLevelness` likewise demoted (aspect-distorted jitter). Both still computed + sent as raw context but assert no fault anywhere.
- **T11** hipShift fires baseline-relative + scored (`RepRecord.shiftTriggered`); its absolute warn is kept only for the panel/context. Still the least trustworthy trigger — one correct fire in four on n=1; needs a dedicated calibration session.
- **T2 bounce has never fired.** `bounceMaxMs` was 150 ms against a measured reversal range of **268.7–1301.5 ms** across 30 reps — provably unreachable. Raised to **300 ms** and gated on `reachedDepth`, because the only sub-300 ms rep in the dataset was a deliberate quarter squat (raising it ungated just converts a dead signal into a shallow-rep false positive). ⚠️ Still zero true positives behind the number.
- **T2 descent is baseline-relative, so a slow warm-up poisons it.** `descentSpikeMult` 1.5 → **2.0**: when reps 1–2 are slower than the working reps the baseline is depressed and normal reps trip the gate (2 false positives in one set at 1.5×). Real users warm up slowly, so this generalises — don't lower it back without checking the warm-up tempo spread.
- Severity zones (`severityFor`/`SEVERITY`) are display/report ONLY — they no longer fire the coach.

## Gemini layer (`ai/gemini.ts`)
- Two live coach tiers: `callPostSet` (images) and `callPostWorkout` (text-only) — plus Analyze's `callFormClip` / `callFormFrame` (see the Analyze section; JSON out, request-wide `mediaResolution`). The request body is built by the pure `ai/requestBody.ts`; without options it is byte-identical to the pre-Analyze body (`check:analyze` proves it). Shared `geminiGenerate` = system prompt + JSON payload + inline JPEGs. **System prompts live in `ai/prompts.ts`** (pure, so Node can test them); the squat strings were moved there byte-identically, then changed 2026-09-18: post-set rule 2 read the view from `rep_context.orientation` (a field of the removed mid-set payload — the post-set payload carries `set_summary.orientation`), and post-workout rules 1/5 now read `sets_observable` / `co_occurred_with_slowing` (rule 5 is shared with push-ups byte-for-byte). `check:squat` asserts neither stale field returns and that every `fault_trends[]` field the prompt names exists in the builder's output. The prompt is chosen by the payload itself (`exercise: "pushup"`; the squat payload has no such field). The mid-set tier is GONE — `requestCoaching()` survives in `gemini.ts` as dead code with zero callers, and `scripts/test_midset.ts` (`npm run test:midset`) still exercises that removed path, so a green run there proves nothing about the live shape.
- Model **`gemini-3.6-flash`** (env `GEMINI_MODEL`; migrated from `3.5-flash` 2026-07-25 — drop-in, request shape unchanged, A/B-verified 200/STOP on a replayed real post-set + post-workout payload). Thinking IS sent (`thinkingConfig.thinkingLevel`: post-set `medium`, post-workout `low`). **Omit temperature** on 3.x (1.0 default; lowering risks thinking loops). `maxOutputTokens`: post-set **8192**, post-workout **4096** — thinking draws from the output budget, so a tight cap truncates mid-thought. Measured headroom on 3.6: post-set 1859 thought + 246 output of 8192; post-workout 489 + 343 of 4096.
- No rate limiter (it gated mid-set only, and went with it). Spend is bounded by the **usage ledger** instead: `usage/ledger.ts` (PURE — all arithmetic, `nowMs` injected) + `usage/usageStore.ts` (localStorage). Rolling-window quota, not calendar-month (no reset job, no timezone call, can't be gamed by waiting for the 1st). The quota gate **fails open** — a bookkeeping error must never block a paying user's coaching. Workouts are **upsert-by-`sessionId`**, which is what makes `completionRate` meaningful (recording only on finish reads a permanent 100%). ⚠️ Client-side = a spend guard for honest users, NOT a security control; the API key is inlined into the bundle. Real enforcement needs the key behind a proxy.
- **When analysis fires** (product decision, changed 2026-10-11): post-set fires the moment a set ENDS — by the hand signal or the End set button, which behave identically (`endSetNow`) — so the debrief is already loading while the lifter walks to the device. The old "Next set → fires the debrief" choice screen is gone. Post-workout fires on End workout / Finish workout; if the last set's post-set is still in flight it WAITS for it (30 s fallback) so the synthesis includes that debrief. **Finish workout pressed while a set is live** still finalizes without a post-set — that's how the calibration protocols keep their last set debrief-free (and their call counts unchanged).
- `extractText` returns `{text, finishReason, usage}`. **finishReason ≠ STOP (e.g. MAX_TOKENS) = truncation** → surfaced as an error, NOT shown as a normal result, and logged (with per-call token usage).
- **View-awareness ↔ payload honesty (keep in sync):** the system prompts forbid the model asserting a plane the camera can't see. The PAYLOAD must match — `firePostSet` nulls SAGITTAL fields on front and FRONTAL fields on side, using **null (not 0/false — false reads as "checked, absent")**. New payload field → classify its plane and null it off-view. `landmarkImplausible` is likewise front-only: it reads frontal-plane geometry, and edge-on the hip width collapses to ~0.007 as a denominator, which flagged **18/18 side reps unreliable** and silently deleted fatigue context from every side set. Those quantities are undefined edge-on, not merely extreme — widening bounds would not have fixed it.
- **Silence from a disarmed check is NOT a pass.** `baseline.valid` + `baseline.checks_disarmed` (names only the checks this view could have run) tell the model which triggers never armed; `POSTSET_SYSTEM` rule 1a forbids reading an empty `triggers_fired` as clean form, **and** forbids substituting an explanation for anything a disarmed check could have caused ("this was not X but rather Y" is the exact failure). Distinct from `baseline_frames_included`, which is only about photos — a set can have both photos and no usable baseline. Without this, set 3 of the 2026-08-02 run was told *"spinal alignment and balance remained solid, no movement faults triggered"* about a set containing a **59.3° lean**.
- **The user never sees a normalized number.** Gap / depth-ratio / velocity-ratio / shift / valgus values are image coordinates — `-0.0023` reads as a rounding error, not "a hair above parallel". The payload carries a precomputed band (`uncounted_reps[].band` via `depthShortfallBand`, `context.velocity_band` via `velocityBand`, both PURE in `checks.ts`; thresholds in `DEPTH_SHORTFALL_BANDS`, keyed by basis because gap and ratio units aren't comparable) and rules 6a/6b let the model speak ONLY the band. **Degrees and rep numbers stay quotable** — they're real units. Severity language scales via `triggers_fired[].severity` + `baseline_multiple` (peak ÷ this set's baseline): `severity` alone is flat, since a 0.32 and a 0.66 hip shift are both "critical" and the debrief called the 2.6× one *"slightly off-center"*. Keep the raw numbers IN the payload — rule 3a's fatigue gate is defined on `velocity_collapse_ratio` — just never spoken.
- **Debriefs render VERBATIM — no markdown parser.** `PostSetReview`/`SynthesisReport` put `review.text` straight into a `<p class="ai-msg">`, so `**bold**` reaches the user as literal asterisks. `.ai-msg` sets `white-space: pre-line` to keep the model's paragraph breaks (default `normal` collapsed a 5-line debrief to 2). Both system prompts' rule 8 forbids markdown for this reason — if you ever add a markdown renderer, relax rule 8 in the same change.
- **Causal claims are evidence-bound (prompt rules `3a`/`5`).** The model previously asserted "fatigue" in every set, including two where `context.velocity_collapse_ratio` was `null`, and contradicted `fault_trends[].worsened_with_fatigue: false` in the post-workout. Fatigue may now be claimed ONLY from `velocity_collapse_ratio < 1.0` (post-set); post-workout gets `fault_trends[].co_occurred_with_slowing` (the fault fired on a rep whose OWN velocity ratio < 1 — co-occurrence, never cause; built in `session/faultTrends.ts`, PURE + tested) plus `sets_observable`. It replaced `worsened_with_fatigue` (2026-09-18), which was `present.includes(lastSetIndex)` — true for any fault in the final set, velocity never consulted — while rule 5 called it the ONLY fatigue authority. `velocity_degradation_per_set` is `null` for an unmeasured set (it was `1`, i.e. "no slowing"); later rep numbers are explicitly not evidence, and causation is banned in **both** prompts — fault→fault *and* context→fault (velocity may establish THAT a rep slowed, never that slowing caused a fault or a "drop in rep quality") (the ban lived only in `POSTSET_SYSTEM` until 2026-07-31 and leaked from the synthesis: *"which directly caused"*, about a trigger that hadn't fired). A session minimum can't localise fatigue either — the payload carries `velocity_ratios_by_rep`, and rule 3a permits attributing fatigue only to a rep whose OWN ratio is below 1.0 (both prior claims pinned it on reps measuring 1.18 and 0.95).
- **API kill-switch:** `geminiEnabled()` also honors a localStorage toggle (`neurofit.apiDisabled`, Settings/`useApiEnabled`) so you can exercise UI + tune raw numbers with zero API calls.

## Push-ups (`pushup/`, added 2026-09-17 — EVERY threshold UNVALIDATED, n=0)
- **Architecture:** the whole per-set engine is PURE (`pushup/session.ts`: tracker, baselines, gates, triggers, counting, Tier-2) and the payload builders are pure too (`pushup/payload.ts`) — so plane-nulling, `checks_disarmed` and the prompt↔payload contract are unit-tested, unlike the squat's inline hook code. `useWorkout` only branches on `exerciseRef` at its exercise-specific seams; **the squat path was left untouched on purpose** (its eval history stays valid). Thresholds + sources: `pushup/config.ts`; calibration run: `PUSHUP_TEST_PROTOCOL.md` ⇄ `PUSHUP_SCRIPT_PROTOCOL_V1` (change together).
- **Aspect space is mandatory.** MediaPipe x is /width, y is /height; on a horizontal body that distortion lands on the decision angles. All push-up geometry uses `[x·W/H, y]` (`CoachCamera` passes the frame size to `onResult`); the squat moved to the same space on 2026-09-18 (see Orientation & metrics).
- **Counting:** shoulder drop `depthRatio=(hUp−h)/hUp`, `h = wrist.y − shoulder.y` (elbow angle is invisible head-on, same reason as the squat knee). Arm 0.20. **Completion IS the lockout gate** (ratio ≤ 0.07 ≈ elbow 150°) — incomplete lockout is the #1 real-world rejection (Kellner 2023). A rise ≥0.25 then re-descent ≥0.10 without lockout closes a separate `lockout_miss` attempt, or pulsed reps silently merge. ≤100 ms median filter on h.
- **Depth basis per view (send the deciding number):** side = bottom **upper-arm angle in degrees** (`upper_arm_angle_deg`, + = shoulder below elbow; presets chest +15 / parallel −5 / above −20); head-on = `depth_ratio` (0.70 / 0.50 / 0.36, from ratio ≈ 0.56·(1+sin θ)). A side null angle counts; a front null ratio never counts. Misses carry `{reason, basis, measured, target, band}`; a rep can miss both gates.
- **Orientation:** score = shoulder x-sep ÷ near upper-arm length (NOT shoulder ÷ torso — that projection changes through a push-up and would flip the view mid-rep). **The lock also requires a plank** (`inPlank`); mid-set reposition does not re-check it (a deep bottom isn't "out of position"). Near-side limb chain via `NearSideSelector` (far limbs are invented).
- **Triggers (warm-up reps 1–2 never fire; 150 ms holds):** P1 body line (side, whole armed rep, no depth gate — sag shows on the ascent): relative ±15° vs warm-up median, absolute backstop sag 25° / pike 35°. P2 descent spike 2.0× (squat lesson); **no bounce threshold — reversal is logged only.** P7 elbow flare (front) `(elbowSpan−wristSpan)/shoulderWidth ≥ 1.0` past depth 0.30 (straight arms collapse it). P11 uneven press (front, post-set) worst shoulder-vs-wrist tilt ≥ warm-up + 8°. Context only: head drop, hand offset, hand width band, knee-variant check, T6.
- **Knees variant** switches the body-line distal point ankle → knee (otherwise every knee push-up reads as sag). User toggle; the side camera's observation is context (`variant_check`), never a fault.
- **Payload specifics:** body-line/tilt severity scales via `baseline_delta_deg`, not a multiple (baselines sit near 0). Body-line and head angles are NOT quotable (floor-camera 2D angle error 13–14°); upper-arm and elbow degrees are. When the relative body-line check is disarmed the absolute backstop still ran — `checks_disarmed` says so. Post-workout uses `co_occurred_with_slowing` (fault on a rep whose OWN ratio < 1) and `sets_observable` so a side-only fault absent from a head-on set isn't read as improvement — the squat post-workout now does the same.
- **Push-up prompts are assembled from the squat's shared rule lines** (`SHARED_*_RULES`, drift-tested byte-for-byte) plus push-up rules 2/3/5/6/6a/6b; `adapt()` throws if a squat anchor string changes. Editing a shared squat rule changes push-ups too — intended.

## Pull-ups (`pullup/`, added 2026-09-23 — EVERY threshold UNVALIDATED, n=0)
- **Architecture = push-ups:** pure per-set engine (`pullup/session.ts`) + pure payloads (`pullup/payload.ts`), all tested by `check:pullup`. Sources are keyed in `pullup/config.ts` ([USMC] PFT, [CFG] CrossFit standard, [NSPHS] China student test, Youdas 2010, Prinold & Bull 2016, Dinunzio 2019, pose counters). Calibration run: `PULLUP_TEST_PROTOCOL.md` ⇄ `PULLUP_SCRIPT_PROTOCOL_V1` (change together). Prompts reuse the same `SHARED_*_RULES`.
- **Counting is inverted — the rest position is the BOTTOM.** `h = shoulder.y − wrist.y`, `pullRatio = (hDown−h)/hDown`, hDown = running max while hanging between attempts. Arms at 0.25 (past any scapular pull, ≲0.16), closes on return ≤0.18, partial-hang segmentation (drop 0.25 then re-rise 0.10). **The bar is fixed, so the wrists are:** wrists 0.15·hDown below their lagging hang reference = let go → an open attempt closes as `dismount` and idle frames are ignored. Without it, lowering the arms after dropping off shrinks h exactly like a pull and arms a phantom rep. Keep `dismountDropRatio < repUpRatio`.
- **Extension is judged at the START of each rep** ([USMC]/[CFG]: every rep starts from a dead hang), so a last rep dropped from the top still counts, and `extension_miss` lands on the rep that STARTED bent (usually because the previous rep wasn't lowered). Primary = 2D elbow ≥150° — a straight arm projects straight from any view, a bend aimed at the camera hides, so a miss is real and a pass may be lenient; gross ratio backstop 0.25; ratio ≤0.12 only when no elbow is readable. The ratio can't be primary: an ACTIVE hang (scapulae down — correct technique) sits 0.05–0.10 above a passive one with dead-straight arms, while 150° vs 180° of elbow moves it only ~0.03.
- **Top = chin vs bar.** chin = mouth + 1.6·(mouth − nose); bar line = per-set MEDIAN of the grip knuckles (index/pinky) while hanging, cleared whenever the grip moves up (`gripEpoch`: standing reach → jump to the bar). Clearance is in hang heights; presets chest +0.15 / chin −0.05 / nose −0.15. No readable face (camera behind the lifter) → fallback basis `pull_ratio` (≈0.976 + clearance, eased). **The basis travels with each miss and each achieved value** — it can change rep to rep when an arm hides the face.
- **Views:** set 1 is HEAD-ON (chin vs bar + both arms); Settings "camera views: head-on only" exists because a doorway bar makes a side view physically impossible — side-only faults then read "not assessed", never clean. Orientation reuses the squat's facing score (a hanging body is vertical like a standing one) and the set **locks STANDING under the bar** — no posture gate, since hanging through the lock + countdown burns the grip.
- **Triggers (all whole-rep, evaluated at close; reps 1–2 never fire):** U1 swing (side) = RANGE of the hand→hip angle over the rep + 1 s pre-arm (a kip's back-swing happens in the hang, before arming). In a slow rep the centre of mass must stay under the bar, so strict reps read a few degrees; abs 20° / +10° vs warm-up. U2 lowering 2.0× (squat lesson). U3 leg drive (side) = max(hip, knee) flexion RANGE ≥30° — a range, because hanging with bent/crossed knees is a style. U4 uneven pull (front) = shoulder tilt − hand tilt past ratio 0.3, +8° vs warm-up. Grip width = context only ([Prinold16] is why "wide" is worth naming).
- **Payload specifics:** elbow angles are NOT quotable (projection-lenient); swing and leg degrees are (in the image plane side-on). Shrugging / active hang, chin craning and lower-back arch have no landmarks — rule 5 lets Gemini describe them only from a frame. DON'T FAKE: "feet off the ground" ([CFG]) is not detected — a standing reach just before the jump can become rep 1's start frame.

## Hand signal & rest (added 2026-10-11 — every gesture threshold UNVALIDATED, n=0)
- **End-of-set signal** (`vision/handSignal.ts`, PURE, tested in `check:squat`): ONE wrist ≥1.2 upper-arm lengths above its shoulder with the elbow above the shoulder, the OTHER wrist below its shoulder, held 1.5 s (200 ms flicker grace). Y-only against the arm's own length in aspect space, so it reads side-on and head-on. Fires once per set (latched), then `endSetNow("hand_signal")`. Settings toggle `neurofit.handSignal` (default on); a centred ring overlay shows the hold, a chime + vibrate confirm it.
- **The shape IS the gate — no "not mid-rep" check.** None of the three exercises makes it during a valid rep (overhead squat and a pull-up hang have BOTH hands up; push-up hands are on the floor). An `isDown` gate would deadlock push-ups: standing up out of the plank can arm a phantom attempt that never closes. Pull-ups alone also skip an attempt in progress. Armed only while `active` and after ≥1 attempt. The "other arm down" side uses a 0.1 visibility floor on purpose: side-on the far arm is invented but follows the body prior, so a far arm on the bar still reads UP and a hang can't pass.
- **Signal onset is a cutoff:** push-up / pull-up attempts that closed at/after the hold began are dropped (`toSetRecord(facing, cutoffMs)`) — they were made getting into the signal. Squat reps can't be (a raised hand doesn't move the hips). Eval log `set_ends[]` records `ended_by`, onset/fire ms and side — the only audit trail for these thresholds.
- **Rest** (`session/rest.ts`, PURE): starts at set end, stops on "Start set N" (`newSet`) — positioning + countdown are NOT counted. Recorded under the set that FOLLOWS it, so set N's post-set carries the rest BEFORE set N (`rest.rest_before_this_set_sec`, `measured_from`, `previous_set` with counts + velocity band); post-workout gets `rest_by_set[]` (+ per-set rep counts). `null` on set 1, never 0. A rest still running at End workout is discarded. Seconds are a real unit → quotable.
- **Prompt rules 4a (post-set) / 5c (post-workout), shared by all three exercises:** rest may be stated; a rest recommendation is allowed ONLY on evidence of decline (`velocity_band` moderate/marked, or fewer counted reps than the previous set); rest is never a cause (same ban as rule 3a / 5a). Both note the figure undercounts — more so when `measured_from` is `end_set_button` (the walk to the device happened before the click).

## Analyze — video form analysis (`analyze/`, added 2026-10-10 — EVERY threshold UNVALIDATED, n=0)
- **What it is:** the user opens a clip they already filmed, steps through it frame by frame (speed 0.1–1×, in/out loop, bookmarks, zoom/pan, mirror, brightness), draws and measures (angle, line, ruler, plumb, circle, arrow, pen, text; calibration from a ruler of known length), sees the skeleton / joint angles / joint trails / an angle-over-time chart, tracks any point (bar end) by template matching, compares two clips (linked, "sync here", overlay), saves a PNG snapshot, and asks Gemini — "Find my form errors" for the whole clip or "Ask about this frame". Researched against Kinovea, Dartfish, OnForm/Hudl Technique, WL Analysis and the AI form-check apps.
- **Where:** `App.tsx` tab `"analyze"`, kept in the URL as **`#analyze`** (the marketing site links `try.neurofit-training.com/#analyze`). Lazy-loaded — the live coach never downloads it. Entry: MENU → ANALYZE A VIDEO, disabled mid-set (leaving unmounts the camera). Settings opened from Analyze closes back to Analyze. Page: `components/analyze/AnalyzeView.tsx`; per clip `hooks/useClipSession.ts` = `useClip` (player) + `usePoseTrack` (pose) + `useClipRecord` (saved notes, undo).
- **The video never leaves the device.** It is opened as an object URL; only the JPEG stills an AI button sends are uploaded. Background work (pose pass, tracking, grabbing JPEGs) runs on a hidden second `<video>` (`components/analyze/frameWalker.ts`) so the user can keep scrubbing.
- **Pose on a recorded clip:** the FULL model (`public/models/pose_landmarker_full.task`, vendored; `createPoseLandmarker({ runningMode, model })` — no options = the live coach's lite/VIDEO, unchanged). A **pass** plays the in/out range through a VIDEO-mode landmarker (`requestVideoFrameCallback`, seek fallback) and **slows playback when detection can't keep up** (down to 1/16) so frames aren't skipped; it **warms the model up on the first frame before playing** — without that the first ~2 s of a clip had no pose (measured). A paused frame gets an **exact** IMAGE-mode detection, which replaces the pass's sample. VIDEO timestamps are a module-level monotonic clock shared by every pass; passes run one at a time.
- **Pure modules + `check:analyze`:** `geometry` (everything in VIDEO PIXEL space = the aspect-space rule, scaled by H), `jointAngles` (2D angles, null when unseen, view guess from the live coach's facing score), `poseTrack`, `reps` (generic cycle finder on whichever of knee/hip/elbow/shoulder swings most; ≥25° range; it says WHERE cycles are, never whether a rep counted or was good), `keyFrames`, `payload`, `annotations`, `pointTracker` (NCC; matches the ORIGINAL patch first — re-anchoring every frame drifted ~5 px in 20 frames; stops when lost instead of guessing), `aiResult`, `cost`, `clipStore`.
- **Cost control (the user pays with their own key):** the whole-clip call sends at most **12 stills** (start / moving out / turnaround / moving back of the first, middle and last found rep; 8 evenly spaced when no reps) at **`mediaResolution: MEDIA_RESOLUTION_LOW`** (280 tokens per image on Gemini 3 vs 1120 by default) — the cap, not the clip length, bounds the cost. The frame question sends the paused frame ±150 ms (3 images, MEDIUM). Long side 768 px, aspect kept. Each button shows an estimate first (`analyze/cost.ts`, prices in `ANALYZE.price` with their source and date — third-party trackers, ~1¢ clip / under 1¢ frame). Answers are saved with the clip, so reopening it never pays twice. Kill-switch, quota and usage ledger apply as for the live tiers; usage tiers **`form_clip` / `form_frame`** (ledger `CallTier`, `GeminiCallObservation`, `UsagePanel` labels, `evalLog` union — change together).
- **Prompts:** `FORM_CLIP_SYSTEM` / `FORM_FRAME_SYSTEM` in `ai/prompts.ts` — ONE general prompt pair for any exercise, sharing rules 3–12 (`FORM_SHARED_RULES`): name the exercise or say unsure; judge only what the view shows (`cannot_judge`, never `looks_good`); pose angles are 2D estimates, quote rounded at most; real faults vs body differences ("no issues" is a valid answer); rank safety first; each issue = what we see + fix + ≤8-word external cue + drill; positions not causes, no fatigue, no fault→fault causation; no medical diagnosis; ask for a re-film when the clip can't be judged; plain words; JSON only. The reply is **JSON with a `responseSchema`** (`formResultSchema`, fields in `FORM_RESULT_FIELDS`), parsed by `parseFormResult` (fence-tolerant, severity-sorted, out-of-range frames → null, markdown stripped) and rendered field by field — an unreadable answer is logged as an error, never shown blank. `check:analyze` asserts every backticked name in both prompts exists in the schema or a payload builder.
- **Saved notes** (`analyze/clipStore.ts`, localStorage `neurofit.analyze.v1`, newest 20 clips): drawings, bookmarks, calibration, in/out, point tracks, exercise name and AI answers, keyed by file name + size + modified time + duration. Never the video. Undo covers the user's edits only — an undo must never discard a paid answer.
- **Testing note:** Playwright's bundled Chromium can't decode H.264 — test with a WebM (real Chrome/Safari play MP4). Gemini can be exercised with no spend by `page.route`-mocking `generativelanguage.googleapis.com`.

## Frame buffers & DON'T-FAKE gotchas
- `ai/frameBuffer.ts` (pure): `LandmarkBuffer` (full-rate, 3 s) + `ImageBuffer` (ring cap 30 ≈ **~7.5 s**, one 640×480 q0.75 JPEG/250 ms). CoachCamera captures/downscales; buffer stays DOM-free.
- **The ~7.5 s ring evicts baseline (reps 1–2) + early-set fault frames 5–12 s before the post-set call fires** (verified n=1, every set). FIXED via a per-set **frame archive** (`postSetFrameArchiveRef` in `useWorkout.ts`, no time limit): reps 1–2 bottom key frames archived at rep-complete (`archiveBaselineFrame`), one peak-severity frame per error TYPE archived at trigger time (`archiveFaultFrame`, direction-aware via `tagMoreSevere`). The ENTIRE archive is what post-set sends — the ring is NOT read by post-set. `PostSetData.baseline_frames_included` (0–2) tells the model how many baseline frames it got; `POSTSET_SYSTEM` rule 1 says 0 ⇒ "no baseline available", never fabricate. **Post-workout is TEXT-ONLY** (no frames — synthesizes over the per-set debrief texts). Archive is reset per set in `newSetTrackers`, AFTER the post-set send.
- Deferred — DO NOT FAKE: `presetIsMobilityBoundary` always `false` (no intent-capture signal — never tell Gemini a preset is a mobility boundary); `preset_reason` always `"preference"`; chest-cave has no landmarks (when T1 fires, the prompt asks Gemini to eyeball rounding from the image).

## State machine & dev tools
- `WorkoutPhase`: positioning → countdown → active → **set-review** → finished. Set-review is a single-stage overlay (rest timer + debrief + Start set N / End workout) rendered as a **CoachCamera child so the MediaPipe model stays loaded between sets** — don't unmount CoachCamera.
- Training mode bodyweight|loaded (`useMode`, localStorage) flips valence (loaded: butt-wink a real trigger, excessive depth flagged) — framed in the prompt, not new geometry.
- **Dev-only eval logger** (`debug/evalLog.ts`, gated `import.meta.env.DEV`/`VITE_EVAL_LOG=1`): DESCRIPTIVE ONLY, never affects logic, inert in prod. Per-rep trigger table (every eligible trigger incl. did-NOT-fire + near-miss — false negatives only surface here) + per-Gemini-call observation (payload/frames/verbatim response/latency/finish_reason/tokens/skips). Exports JSON+MD; the `front_depth_gate` row validates the front depth targets. Pre-fill intended faults via `window.__neurofitEval.setScript({"1:3":"fast descent"})`.
- **`SCRIPT_PROTOCOL_V2`** (in `evalLog.ts`) is the ground truth labelling each rep of a calibration run; **`TEST_PROTOCOL.md`** is the human-readable version the lifter follows. **Change both together** — a drift between them silently mislabels the entire dataset.
